# MCP server — design (draft, v0.4.0)

> Status: **design, not built.** Goal: any MCP-capable agent (Hermes, Claude Code, Codex)
> can use Ojo de Gato, including an agent on a remote server reaching a camera
> Mac at home over Tailscale.

## The core question: agents can't watch video

An LLM agent can read text and look at **images**. It can't watch an mp4. So the server
gives the agent three kinds of output, and each one is labelled with where it came from:

| What | MCP content | Source of truth |
|---|---|---|
| Facts: last seen, sightings, verified events, vision state, darkness | JSON text | the deterministic pipeline (`events.sh`, `motion-stats.sh`) |
| Pictures the agent can look at: live snapshot, an event's best frame, a contact sheet of a clip | `image` blocks (JPEG, downscaled) | the camera, with the frame Apple Vision was most confident in |
| Video for the human: last-movement clip, day recap | **not sent through MCP**: a URL served by the MCP server over the tailnet, or delivered straight to Telegram by ojogato | `clip.sh` / `recap.sh` |

The honesty rule survives the change. Counts and "was there a cat" always come from the
pipeline. If the agent describes an image, that description is its own observation, and the
tool descriptions say it must be labelled as one.

## Tools (all read-only)

| Tool | Args | Returns |
|---|---|---|
| `camera_status` | — | JSON: `last_seen_min`, `sightings_6h`, `sightings_12h`, `vision` (on/stale/off), `dark`, `paused`, `detector_alive`, `live_url` |
| `list_events` | `hours=6`, `real_only=true`, `since_epoch?` | JSON list from `events.sh --json`: start, end, verdict (pet/person/none), score, frame counts, `event_id` |
| `get_snapshot` | `max_width=768` | image (live frame) + JSON caption (`taken_at`, `luma`, `dark`) |
| `get_event_frame` | `event_id` | image (the event's best Vision frame) + verdict/score |
| `get_last_clip` | `deliver="url"\|"telegram"` | JSON (event time, verdict, duration, `url` if deliver=url) + a 3-frame contact-sheet image |
| `get_recap` | `hours?`, `max?`, `deliver="url"\|"telegram"` | JSON (moments, times, `url`) + a contact-sheet image |

Not exposed in v1: `on`/`off`, config, setup. A monitoring tool that an agent can switch off
would weaken the watchdog's guarantee.

`deliver="url"` is the v1 path for remote agents: your phone is on the tailnet, so the agent
relays the link and you tap it. (Later, an agent could fetch the mp4 and send it through its
own bot.) `deliver="telegram"`
keeps today's behaviour (the scripts send with ojogato's bot).

## Alerts: MCP is pull, not push

MCP clients don't wake up when a server sends a notification. So:

1. **The watchdog keeps texting directly**, as now. Safety alerts never depend on an agent.
2. **Polling:** an agent cron calls `list_events(since_epoch=…)` to see new sightings
   ("anything new since 9am?").
3. **Optional webhook (v0.4.x):** `OJOGATO_WEBHOOK_URL`. On each new *verified* event,
   ojogato POSTs `{event_id, verdict, score, time}` so an agent (Hermes has a webhooks skill)
   can react, for example by fetching `get_event_frame` and messaging you.

## Transport and security

- **Implementation:** Python 3.9+ (the version Xcode Command Line Tools installs on the camera Mac), stdlib only, matching the repo's no-dependency approach. MCP
  is JSON-RPC: newline-delimited over **stdio** for a local agent, and a stateless
  **Streamable HTTP** endpoint (`POST /mcp`, JSON responses, no SSE) for remote agents.
  Needs only `initialize`, `tools/list` and `tools/call`.
- **Binding:** `127.0.0.1` by default. `OJOGATO_MCP_BIND=tailscale` binds to the Mac's
  tailnet IP. It never binds to `0.0.0.0`.
- **Auth:** `OJOGATO_MCP_TOKEN` bearer token, generated by `ojogato setup`, required for
  `/mcp`. `/media/*` uses short-lived signed paths instead of a header, because a phone
  opening a link can't send one.
- **Sessions:** returns an `Mcp-Session-Id` on `initialize` and accepts it afterwards.
  Hermes's client does a session handshake (that's how its Rappi MCP connects).
- **Service:** `com.ojogato.mcp` launchd agent, managed alongside the other services
  (`ojogato on|off|status`).
- **Privacy:** images and video of your home only travel over the tailnet, to the agent you
  configured. If that agent sends a frame to a cloud LLM, that's the agent's own model
  making that call, and the README says so plainly.

## Pipeline changes needed

- Standalone digests: a `com.ojogato.digest` launchd job, so 9am/9pm digests don't need an
  agent's scheduler.

- `report.sh` / a new `status.sh --json`: machine-readable status (today it only prints a
  human caption).
- `clip.sh`: print metadata + path without sending (`recap.sh` already has `--no-send`).
- Stable `event_id` (`start_epoch`) in `events.sh --json` and a way to resolve it to its best
  frame.
- Contact sheet: one ffmpeg `tile` call over N frames sampled from the clip.

## Testing without the camera

A fixture `OJOGATO_HOME` (fake `verdicts.tsv`, motion frames, a short test recording) runs
every tool without a camera. End-to-end on the real camera Mac before release.
